# 积分包流水与缓存字段兼容

## 1. 查看位置与含义

设置中的国内账号页展开“积分包流水”，显示当前账号最近 20 条记录。读取账号余额时采集上游快照；流水的刷新按钮仅重读本地记录，不请求收费模型。首次安装前的历史无法恢复，记录时间是快照读取开始时间，并非实际扣费时间。

仅核对国内个人账号通用积分（`available_endpoint=0`）；Work 专用池、企业租户额度与国际订阅不混入。`usage.credits_amount` 是累计已消耗量，剩余等于额度减累计消耗。只有明确存在 usage 对象且未提供 credits_amount 时按未使用的零处理；缺少 usage 对象或非法计数拒绝记账。

## 2. 差分分类

| 类型 | 依据与限制 |
| --- | --- |
| 初始余额 | 首次完整快照的可用余额；不是新发放 |
| 发放 | 同包累计额度增长；首次出现的新包只确认当时可见余额 |
| 消耗 | 同包累计消耗增长，记负数；不绑定请求或会话 |
| 到期 | 先前有余额的包到达已知到期时间，记剩余额度减少 |
| 调整 | 未到期包消失、重新出现、计数重置或额度缩减等不能确定原因的变化 |

同包同时发放与消耗会分别记录，差分净额与余额变化一致。同标识包先聚合；包到期期间发生的晚结算不能与到期余额可靠拆分，因此按到期处理。不完整快照和错误响应不覆盖基线。

**这些是账号快照差分，不能认定某条请求扣了这些积分。** 账号可能在其他客户端并发使用，积分发放及到期也会改变余额。记录不写入逐请求费用文件，不用于会话成本、官方价格换算或单价校准。

## 3. 本地持久化与接口

文件位于 `$DSH_HOME/storages/dsh-connect-trae/credit-journal.json`，使用文件锁及原子写入。账号和包标识哈希后保存，不记录昵称、令牌或 responseId。不同账号分别建立基线，读取期间固定凭据，旧于或等于上次开始时间的响应忽略。损坏文件报错，不静默重建历史。

每账号最多保留 2000 条事件，轮替计数随文件保存；界面展示最近 20 条，发生轮替时显示说明。消失包保留标记，避免再次出现被误认成新发放。

只读本地接口：`GET /plugins/dsh-connect-trae/credit-history?region=cn&accountId=<local-account-id>`。沿用本地来源校验并确认账号存在；返回 `source=account-snapshot-diff`、`scope=account`、余额、快照时间、事件及轮替计数。它不触发上游扣费。未建立基线时余额与时间为 null。

## 4. 缓存字段兼容

SOLO 实际 SSE 转发及 Raw Chat 解码器共用规则。保留原始 usage 字段，在 `prompt_tokens_details` 中补充规范缓存计数：

| 规范字段 | 候选优先级（从左到右） |
| --- | --- |
| cached_tokens | 现有规范值 → prompt_cache_hit_tokens → cache_read_input_tokens → input_tokens_details.cached_tokens → 裸 cached_tokens |
| cache_write_tokens | 现有规范值 → cache_creation_input_tokens → input_tokens_details.cache_write_tokens |

明确的零优先于其他格式；只接受有限非负数，缺失或非法值不补零。不推断上游未报告的缓存折扣，不改变总输入 token 的计数口径。Raw Chat 原始响应目前仍透传，本次解码兼容不代表所有 Raw wire 字段已重写。

## 5. 验证与来源
