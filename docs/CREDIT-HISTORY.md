# 积分包流水与缓存字段兼容

## 1. 查看位置与含义

用户在设置中的国内账号页展开“积分包流水”后，可以查看当前账号最近 20 条记录。插件在读取账号余额时采集上游快照，并根据快照变化生成流水；用户点击流水中的刷新按钮时，插件只重读本地记录，不请求收费模型。

插件无法恢复首次采集快照之前的历史。流水中的时间表示插件开始读取快照的时刻，不表示实际扣费时刻。

插件只核对国内个人账号的通用积分（`available_endpoint=0`），不将 Work 专用池、企业租户额度或国际订阅计入该流水。上游的 `usage.credits_amount` 表示累计消耗量，插件用积分额度减去累计消耗量，计算剩余额度。

只有上游明确提供了 `usage` 对象、但未提供 `credits_amount` 时，插件才将消耗量按零处理。如果快照缺少 `usage` 对象，或计数包含非法值，插件会拒绝用该快照记账。

## 2. 差分分类

| 类型 | 依据与限制 |
| --- | --- |
| 初始余额 | 首次完整快照的可用余额；不是新发放 |
| 发放 | 同包累计额度增长；首次出现的新包只确认当时可见余额 |
| 消耗 | 同包累计消耗增长，记负数；不绑定请求或会话 |
| 到期 | 先前有余额的包到达已知到期时间，记剩余额度减少 |
| 调整 | 未到期包消失、重新出现、计数重置或额度缩减等不能确定原因的变化 |

插件会先合并标识相同的积分包，再计算快照差分。同一积分包同时发生发放和消耗时，插件会分别记录两类事件，使差分净额与余额变化保持一致。积分包到期期间如果还发生了延迟结算，插件无法可靠区分消耗量与到期失效量，因此将该变化归为到期。收到不完整快照或错误响应时，插件保留原有基线。

**这些是账号快照差分，不能认定某条请求扣了这些积分。** 账号可能在其他客户端并发使用，积分发放及到期也会改变余额。插件不会将这些记录写入逐请求费用文件，也不会用它们计算会话成本、换算官方价格或校准单价。

## 3. 本地持久化与接口

插件将流水保存到 `$DSH_HOME/storages/dsh-connect-trae/credit-journal.json`，通过文件锁和原子写入保护文件。插件会对账号及积分包标识计算哈希后保存，不记录昵称、令牌或 responseId。

插件为不同账号分别建立基线，并在一次读取期间固定所用凭据。响应对应的读取开始时间早于或等于上次记录时间时，插件会忽略该响应，避免旧数据覆盖新数据。流水文件损坏时，插件会返回错误，不会自动重建并覆盖已有历史。

插件为每个账号最多保留 2000 条事件，并将移除旧事件的累计数量一并写入文件。界面展示最近 20 条事件，在旧事件已被移除时显示说明。插件还会保留已消失积分包的标记，避免将它们再次出现误判为新发放。

客户端通过只读本地接口 `GET /plugins/dsh-connect-trae/credit-history?region=cn&accountId=<local-account-id>` 查询流水。接口会校验请求来源并确认账号存在，再返回 `source=account-snapshot-diff`、`scope=account`、余额、快照时间、事件和旧事件移除计数。该接口不调用上游计费服务；账号尚未建立基线时，接口返回的余额和时间均为 null。

## 4. 缓存字段兼容

SOLO 的 SSE 转发流程与 Raw Chat 解码器共用缓存字段兼容规则。处理响应时，插件保留原始 usage 字段，并在 `prompt_tokens_details` 中补充以下规范缓存计数：

| 规范字段 | 候选优先级（从左到右） |
| --- | --- |
| cached_tokens | 现有规范值 → prompt_cache_hit_tokens → cache_read_input_tokens → input_tokens_details.cached_tokens → 裸 cached_tokens |
| cache_write_tokens | 现有规范值 → cache_creation_input_tokens → input_tokens_details.cache_write_tokens |

插件按表中优先级选择第一个有效值；明确的零也会优先于后续候选。插件只接受有限非负数，不会将缺失或非法值补为零，也不会推断上游未报告的缓存折扣或改变总输入 token 的计数口径。Raw Chat 的原始响应仍按原样转发，因此解码器兼容并不表示插件已重写所有 Raw wire 字段。

## 5. 验证与来源

回归测试使用合成夹具，验证差分分类、同包聚合、账号隔离、重复及乱序读取、缺项保护、接口来源限制、账号切换展示，以及 SOLO 流转发中的缓存字段保留。维护者分别记录现场只读检查和合成回归的结果，没有使用真实账号进行扣费实验。

本项目参考 wild-work 的积分账本与 usage 兼容处理思路，独立实现了上述功能；来源见 [第三方声明](../THIRD_PARTY_NOTICES.md)。
