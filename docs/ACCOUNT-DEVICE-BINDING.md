# 账号设备绑定与 4017 排查

## 1. 依据与边界

维护者在处理 4017 时参考了 wild-work 的提交 `a3c6993` 和 issue #60 中的维护者回复。这些历史对照记录显示，多账号共享设备号可能与部分 4017 风控有关。调查时，原 issue #70 已无法访问，因此本项目只采用仍可读取的提交、维护者回复和回归测试作为依据；这些样本不能证明所有 4017 都由设备共享引起。

参考来源：<https://github.com/rockswang/wild-work/commit/a3c6993cc1ec76bea6075874238e2a4dfdabbc6a>、<https://github.com/rockswang/wild-work/issues/60#issuecomment-6051679763>。

本插件读取已有 Trae 登录，不创建新的注册设备，不自动随机替换设备号。设备身份与刷新签名密钥必须属于授权时的同一份登录记录。

## 2. 已实现的处理

1. 插件从本机客户端读取登录状态时，会从同一份存储快照解析凭据和设备身份，避免在切换账号期间混用两个账号的数据。
2. 插件将设备身份随账号保存到私有凭据副本，并在刷新令牌时保留该绑定。重新登录产生到期时间更晚的有效凭据时，插件会整体更新凭据和设备身份；对于使用同一令牌的旧副本，插件可以补齐设备绑定，但不会为不同令牌推测设备身份。
3. 插件在普通对话、目录查询、账号池换号、令牌刷新和签到中，均优先使用实际请求账号保存的设备身份。执行签到时，插件会从同一次凭据读取中取得令牌和设备头；执行指定账号的操作时，插件使用该账号的客户端。
4. 状态接口只提供是否绑定及共享账号名称，不返回设备号、机器号或签名密钥。账号列表与账号池显示缺少绑定或共享设备的提示；提示不保证重新登录能解除风控。
5. 插件导出的文件可能包含设备绑定和签名私钥，用户应按密码保管该文件。导入时，插件会校验字段及区域；导入预览接口不会返回这些秘密值。
6. 签到接口返回 9095 后，插件只跳过使用同一设备的后续账号，继续处理绑定到其他设备的账号。插件将缺少绑定的旧账号归为同一个兼容设备组；其他设备签到失败时，界面不会因此禁用已有独立设备绑定的账号。

## 3. 旧账号如何处理

旧凭据缺少设备绑定时，插件会继续按原有安装身份解析请求，并显示未绑定提示，以兼容升级前保存的账号。只有插件能够确认同一令牌或取得完整的新登录记录时，才会写入设备绑定。

若 4017 持续出现，用户可在 Trae 重新登录该账号，再刷新插件账号列表。导入账号应使用来源端导出的完整凭据与设备绑定。不要仅修改设备号，也不要反复重新登录消耗设备名额。

## 4. 验证

`tests/account-device.spec.ts` 覆盖设备快照持久化、刷新保留、重新登录更新、导入导出、备用账号请求头、签到单次读取、共享诊断和设备级签到隔离；`tests/account-device-render.spec.tsx` 覆盖提示与账号行结构。对账号身份优先级及私有副本读取进行了反向变异验证。

这些回归使用合成夹具，不代表真实账号的 4017 已解除。真实效果需要在正常请求中观察。
