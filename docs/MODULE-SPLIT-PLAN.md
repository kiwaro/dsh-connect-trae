### 2.1. 依赖方向与兼容性

入口负责注册与编排，调用配置及功能模块；纯函数和类型模块不反向引用入口。账号池直接依赖独立的设置写入模块，解除对主卡片运行时代码的循环依赖。原入口继续导出原有 API，根入口运行时导出集合保持 175 项。

主卡片和账号池的状态管理及主 JSX 仍在原组件中。本次提取的职责以表中模块为准。账号选择及重试继续使用 Trae 原实现，持久化与收费路径也保持原行为。

## 3. 自检发现与修复

### 3.1. Windows 进程检测

原构建提醒脚本依赖 POSIX `ps`，在 Windows 上会漏报运行中的 DSH。维护者新增了 `scripts/live-host-process.mjs`：脚本在 Windows 上使用只读 CIM 查询，在其他平台继续使用 `ps`，查询失败时不阻断构建。回归测试验证了 Windows、POSIX 和查询失败三种情况。

### 3.2. 凭据诊断串号

原 `scripts/verify-windows.mjs` 为多个候选共用同一条凭据副本路径。脚本写入第一个真实账号后，后续不存在的候选也可能从该副本读出账号，造成误报。修复后，脚本为每个候选使用独立临时路径，并在进程退出时删除临时副本。回归测试模拟凭据副本读取流程，确认不存在的候选不会读出其他账号，且输出不包含账号名。
