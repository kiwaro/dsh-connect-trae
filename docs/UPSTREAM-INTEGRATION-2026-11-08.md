## 2. 账号反馈

| 场景 | 显示位置 | 内容 |
| --- | --- | --- |
| 自动换号后请求被接纳 | 回复正文开头、账号池活动记录 | 前一账号、失败原因、已切换账号[账号A]继续请求 |
| 请求最终失败 | DSH 本轮错误、账号池活动记录 | 失败账号名、错误分类、上游异常原因 |
| 响应流中断 | DSH 流错误、账号池活动记录 | 账号名与中断原因；不重放已经开始的请求 |
| 手动切换成功 | 设置卡片、积分弹窗 | 已切换账号[账号A]，后续请求使用此账号 |
| 手动切换失败 | 对应卡片或弹窗的错误行 | 目标账号名、设置保存的实际失败原因 |

活动记录按面板隔离，在当前插件进程内最多保留 30 条，重启清空；界面随用量读取更新。
积分弹窗显示最近 5 条活动，并在账号行展示已有的失败探测原因。
凭据内容在持久化失败探测记录、活动记录和响应错误之前脱敏；请求正文不进入活动记录。
手动切换仍先关闭本区域自动选号，保留成员名单，然后保存并回读确认选定账号。

## 3. 验证方法

- 修复前先运行失败回归，覆盖自动换号、最终拒绝及两个手动入口的成功提示。
- 用本地脚本客户端模拟限流、额度不足、工具调用帧和流中断，不访问模型上游、不消耗积分。
- 检查设置被拒绝时不显示成功；检查快速及完整用量响应均带本面板活动记录。
- 检查活动清空、容量限制、面板隔离及 token / Authorization / Cookie 脱敏。
- 执行 `pnpm run check`、隐私扫描，并在部署后验证 DSH 插件实际加载。
